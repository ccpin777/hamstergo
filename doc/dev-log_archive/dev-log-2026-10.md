# HamsterGo Dev Log — 2026-10

## 2026-10-29 — 釐清同步失敗與帳號模式自動上傳

- 帳號模式的自動上傳改用帳號密碼判斷是否可加密，不再誤依賴進階同步設定的加密密碼。
- 上傳和下載失敗時區分登入失效、資料過大、HTTP 錯誤及連線失敗，避免一律提示設定錯誤。
- 檢查確認目前跨裝置流程只有自動上傳，另一台裝置仍須手動下載；未改變覆蓋或衝突處理行為。
- 驗證：10 個 Node 同步回歸測試通過，`git diff --check` 通過，預設 Worker 的公開協定端點回應 protocol 2。未取得使用者裝置的錯誤紀錄，也未做兩台真實裝置的端到端測試。

## 2026-10-25 — 防止雲端同步覆蓋較新資料

- Worker 的同步上傳改用既有 `version` 欄位做條件式寫入；版本不符回傳 `409`，未帶版本的舊前端回傳 `428`。不需資料庫 migration。
- 前端記住各同步設定最後確認的版本，自動上傳遇到衝突會停止；下載前確認並匯出本機 JSON 備份。同步期間的本機修改會保留並重新安排上傳。
- 新前端會先檢查 Worker 是否支援條件式寫入，避免新版前端對舊 Worker 送出不安全的上傳。部署順序為 Worker、再前端；此處尚未部署。
- 驗證：8 個 Node 回歸測試通過，涵蓋舊版本、重複初次上傳、缺少版本、舊 Worker、跨視窗修改及下載期間修改；前端與 Worker JavaScript 語法檢查通過。未做真實 D1 或瀏覽器同步測試。
